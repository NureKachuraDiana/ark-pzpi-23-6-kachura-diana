2 ЗАВДАННЯ
Метою практичного заняття є формування навичок застосування методів рефакторингу коду програмного забезпечення на основі реальних прикладів. У межах роботи було обрано три методи, описані Мартіном Фаулером у книзі «Refactoring. Improving the Design of Existing Code», та продемонстровано їх використання на прикладах програмного коду мовою PHP.
У ході виконання роботи подано опис проблем, які вирішуються кожним методом, наведено фрагменти коду до та після рефакторингу, а також пояснено, яким чином обрані методи впливають на якість та підтримуваність програмного забезпечення. Додатково підготовлено презентацію та відеозапис доповіді, а звіт оформлено у форматах PDF і TXT відповідно до вимог ДСТУ 3008:2015.
У роботі розглядаються три методи рефакторингу: Push Down Method, Self Encapsulate Field та Consolidate Duplicate Conditional Fragments. Застосування цих методів демонструє можливості покращення архітектури коду, підсилення інкапсуляції та усунення дублювання логіки, що є важливими складовими якісного програмного забезпечення. 
3 ОПИС ВИКОНАНОЇ РОБОТИ
У процесі виконання практичного завдання було здійснено детальне опрацювання теоретичних основ рефакторингу коду програмного забезпечення та вивчено підходи, запропоновані Мартіном Фаулером у його фундаментальній праці «Refactoring. Improving the Design of Existing Code». Особливу увагу приділено методам, що найчастіше застосовуються під час оптимізації вже написаного коду, коли необхідно покращити його архітектуру без зміни поведінки програми. Було обрано три методи, які охоплюють різні аспекти структурування коду та дозволяють продемонструвати різні техніки підвищення його якості.
Підготовка до практичної частини включала аналіз проблем, що виникають у реальному програмному коді: дублювання логіки, порушення інкапсуляції, надмірне навантаження на базові класи та плутаність у структурі умовних операторів. Для кожної з цих проблем було підібрано метод рефакторингу, який, відповідно до рекомендацій Фаулера, є найбільш доцільним для її розв’язання. Це дозволило сформувати чітку методологію роботи: визначення недоліку → застосування відповідного методу → оцінка змін.
У рамках детального аналізу було підготовлено вихідні фрагменти PHP-коду, що містили описані проблеми. Для кожного методу ці фрагменти проаналізовано з точки зору підтримуваності, читабельності та відповідності принципам об’єктно-орієнтованого проєктування. Було визначено, які саме аспекти коду ускладнюють його подальше використання: зайві методи в батьківських класах, прямий доступ до внутрішніх полів об’єктів або повторення однакових інструкцій у гілках умовних операторів. Це стало відправною точкою для подальшого рефакторингу.
Після цього для кожного методу було розроблено і представлено оновлений варіант коду. Рефакторинг виконувався з дотриманням вимоги незмінності зовнішньої поведінки програми: змінювалася виключно архітектурна організація та внутрішня структура. Для Push Down Method метод було перенесено з базового класу в підклас, де він дійсно виконує логіку. Для Self Encapsulate Field прямий доступ до змінних було замінено інкапсульованими методами get/set. Метод Consolidate Duplicate Conditional Fragments дозволив скоротити дублювання й спростити умовну конструкцію.
Після виконання рефакторингу було проведено аналіз покращень. Оновлений код став компактнішим, логічнішим та легшим для підтримки в довгостроковій перспективі. Зменшення дублювання дозволило знизити ризик помилок у разі майбутніх змін, а впорядкування структури класів сприяло дотриманню принципів SOLID. Крім того, чітка інкапсуляція даних підвищила безпеку та передбачуваність роботи класів.
Завершальним етапом роботи було оформлення презентації, відеозапису доповіді та підготовка повного звіту відповідно до вимог ДСТУ 3008:2015. У презентації продемонстровано послідовність мислення: від виявлення проблеми до покрокового покращення коду. Відеозапис містив коментарі та пояснення щодо кожного етапу рефакторингу. Таким чином, практична робота не лише ілюструє можливості застосування конкретних методів рефакторингу, але й формує системне розуміння їх впливу на якість та надійність програмного забезпечення. 
4 ВИСНОВКИ
У ході виконання практичного завдання було досліджено три методи рефакторингу коду програмного забезпечення: Push Down Method, Self Encapsulate Field та Consolidate Duplicate Conditional Fragments. Аналіз їх застосування дозволив оцінити практичний вплив структурних змін на якість програмного коду, його читабельність та підтримуваність, зберігаючи при цьому незмінною функціональність програми.
Застосування Push Down Method сприяло впорядкуванню ієрархії класів і усуненню зайвої логіки в базових класах, а Self Encapsulate Field забезпечив необхідний рівень інкапсуляції та контроль над зміною внутрішнього стану об’єктів. Метод Consolidate Duplicate Conditional Fragments дозволив зменшити дублювання коду та спростити умовні конструкції, що позитивно впливає на стабільність і передбачуваність подальших змін.
Отримані результати підтверджують ефективність системного рефакторингу як одного з ключових інструментів підвищення якості програмного забезпечення. Використання методів, описаних Мартіном Фаулером, дозволяє оптимізувати архітектуру коду, зменшити технічний борг та забезпечити довготривалу підтримку і розвиток програмних проєктів.

В.1 Код до/після для Push Down Method
Код до рефакторингу (метод оголошено в базовому класі, але використовується лише для менеджера):
<?php

class User
{
    protected string $name;

    public function __construct(string $name)
    {
        $this->name = $name;
    }

    // Метод фактично потрібен лише для менеджера
    public function calculateCommission(float $sum): float
    {
        return $sum * 0.10;
    }
}

class Customer extends User
{
    // Клієнт не використовує calculateCommission()
}

class Manager extends User
{
    // Менеджер використовує calculateCommission() з базового класу
}

Код після рефакторингу (Push Down Method — метод перенесено до підкласу):
<?php

class User
{
    protected string $name;

    public function __construct(string $name)
    {
        $this->name = $name;
    }
}

class Customer extends User
{
    // Клієнт як і раніше не має комісії
}

class Manager extends User
{
    // Метод "опущено" в підклас Manager
    public function calculateCommission(float $sum): float
    {
        return $sum * 0.10;
    }
}

В.2 Код до/після для Self Encapsulate Field
Код до рефакторингу (прямий доступ до поля знижки):
<?php

class Order
{
    // Поле доступне ззовні й змінюється без контролю
    public float $discount = 0.0;

    public function applyPromoCode(string $code): void
    {
        if ($code === 'SALE10') {
            $this->discount = 0.10;
        }
    }

    public function getTotal(float $price): float
    {
        return $price - $price * $this->discount;
    }
}

Код після рефакторингу (Self Encapsulate Field — доступ тільки через get/set):
<?php

class Order
{
    // Поле інкапсульовано
    private float $discount = 0.0;

    public function setDiscount(float $discount): void
    {
        // Додаткова логіка контролю значення
        $this->discount = max(0.0, min($discount, 0.5));
    }

    public function getDiscount(): float
    {
        return $this->discount;
    }

    public function applyPromoCode(string $code): void
    {
        if ($code === 'SALE10') {
            $this->setDiscount(0.10);
        }
    }

    public function getTotal(float $price): float
    {
        return $price - $price * $this->getDiscount();
    }
}

В.3 Код до/після для Consolidate Duplicate Conditional Fragments
Код до рефакторингу (дублювання однакових інструкцій у гілках if/else):
<?php

if ($userRole === 'manager') {
    $order->status = 'approved';
    $order->updated_at = new DateTime();
    $order->save();
} else {
    $order->status = 'pending';
    $order->updated_at = new DateTime();
    $order->save();
}

Код після рефакторингу (Consolidate Duplicate Conditional Fragments):
<?php

if ($userRole === 'manager') {
    $order->status = 'approved';
} else {
    $order->status = 'pending';
}

// Спільні дії виконуються один раз
$order->updated_at = new DateTime();
$order->save();
